# Независимая проверка восстановления ошибки клиента

**Pass в проверенном объёме.** Прочитаны текущий `src/server/public/shared/conversation-client.js`, существующие тесты клиента и новые `test/conversation-resume-recovery.test.js`. Исходники общего клиента этим рецензентом не менялись. Браузер и платные API не использовались.

Подтверждено чтением и независимым запуском 16/16 тестов:

- Принятая сервером ошибка и её retryable сохраняются в snapshot. Новый клиент показывает её до и после бесплатного actionless resume.
- Восстановление ошибки применяется только при совпадении ID разговора, revision и failedAction. Это не подмена нового успешного состояния старой ошибкой.
- Reload не отправляет action retry и не повторяет planner. Следующий явный retry использует принятое состояние, без повторного добавления исправленной реплики.
- retryable false сохраняется после reload и блокирует прямой client.retry. Текст черновика остаётся сохранённым.
- Новый подбор снимает старое восстановление; возврат к предыдущему неуспешному разговору восстанавливает его ошибку бесплатным resume и сохраняет самостоятельную новую поправку.

Дополнительно выполнены три независимых сценария через in-memory storage/fetch, без изменения файлов тестов: (1) сетевой сбой самого бесплатного resume, затем явный повтор остаётся actionless и возвращает прежний бюджетный запрет; дальнейший retry заблокирован; (2) новая revision снимает прежнюю ошибку; (3) изменённый failedAction снимает прежнюю ошибку. Все прошли, HTTP/API0.

Граница вывода: проверено сохранение **ошибки принятого серверного состояния**. Это не утверждение, что любой потерянный сетевой запрос сохраняется как повторяемая команда после закрытия окна. Не подтверждается и возможность отменить уже отправленную генерацию. Расход контролирует прежний backend ledger; клиентская кнопка не заменяет этот контроль.

Отдельная подтверждённая граница app.js — успешный Retry после сетевого сбоя Back должен завершать то же восстановление текста, что обычный Back. Она исправлена в собственных UI-файлах: сохранённый descriptor содержит ID разговора и удалённый turn, переносится через неуспешные попытки, применяется только к совпавшему возвращённому вопросу без существующего черновика. Это не изменение общего transport-клиента и не новый API-запрос. Локальный набор UI32/32 и синтаксическая проверка прошли.

**Живое подтверждение основного агента:** Chrome сохранил ошибку с retryable true через reload; явный Retry не добавил повторную реплику. Бюджетная ошибка с retryable false была видна без кнопки Retry до и после reload. Отдельно пройдено: принятая неуспешная поправка → Back/обрыв → Retry/обрыв → Retry/успех. Восстановлен точный текст «Сегодня хочу гонки вместо исследования мира.», зафиксированы три одинаковых запроса Back с revision4, planner0/picker0 и платных обращений0. Скриншот: `browser/back-after-two-network-errors.png`. Это подтверждение родительского агента; автор независимого source-review сам браузер не открывал.
