# Адресная независимая проверка ночных UI-изменений

01.11.2026. Проверены `app.js`, `question-drafts.js`, `answer-view-state.js`, `feedback-view-state.js`, `time-budget-view.js`, `conversation-client.js` и связанные тесты. Исходники продукта в рамках этого UI-review не менялись; исправления выполнял ux_audit после передачи находок. Браузер и настоящий API этот рецензент не использовал. Авторство shared feedback/core/client recovery отдельно оговорено ниже и не выдаётся за независимую проверку собственного кода.

## Подтверждённые существенные находки

1. **Черновик незавершённого ответа переживал смену желания как текущий ответ.** Ключ V2 учитывал смысл/формулировку вопроса и число принятых ответов на него, но не новую поправку. В открытом вопросе осталось «Хочу сюжет»; пользователь применил «Теперь гонки без сюжета»; planner вернул такой же общий вопрос с теми же options. Прежний вопрос ещё не был отвечен, поэтому ключ не изменялся и старые слова становились текущим ответом. Воспроизведено настоящим helper на двух состояниях с разными correction turns.

   **Исправлено:** V3 включает последнюю действующую correction epoch, смысл вопроса и occurrence внутри epoch. Редактирование условий сохраняет тот же ключ; возврат к более раннему состоянию возвращает прежний ключ. Однократная миграция V2 сохраняет уже введённые слова при обновлении, но не запускается заново при каждой новой поправке в том же разговоре. Просмотрены call sites и новые отрицательные/положительные тесты.

2. **Возврат предыдущего разговора старого формата требовал перезагрузки для показа его черновика.** Миграция выполнялась только при открытии модуля. Кнопка «Вернуть прошлый подбор» корректно возвращала старые state/drafts через настоящий client, но scoped draft оставался пустым: слова лежали под старым ID-ключом. Чистое воспроизведение дало `visibleScopedDraft:''` при сохранённом `preservedLegacyDraft:'Не потерять прежнее желание'`.

   **Исправлено:** `ensureQuestionDraftMigration()` вызывается перед первым чтением текущего экрана в render и защищена marker V3 + dialogue ID. Поэтому восстановленный разговор мигрирует до первого показа; новые поправки того же разговора не подтягивают старые слова снова. Смена разговора и восстановление его старого состояния не отправляют модельный запрос.

3. **Back после поправки из отдельной формы не возвращал её текст в редактируемый ответ.** Поправка была принята как turn, а её поле очищалось после успеха; scoped draft для служебного correction-question не создавался. После Back снимок возвращал этот вопрос, но textarea была пустой.

   **Основной маршрут исправлен:** перед Back сохраняется удаляемый turn; `backDraftSeed` восстанавливает его слова/selected только при совпадении возвращённого question ID и отсутствии существующего cache. Уже сохранённый пустой draft не перезаписывается; context-resume с другим question ID не затрагивается. Новые тесты этого helper просмотрены, проходят.

   **Смежный маршрут сетевого повтора тоже исправлен и перепроверен:** если первый Back не дошёл, Retry раньше обходил локальный seed-код navigate. Теперь `prepareBackDraft` сохраняет конкретный turn, а `finishBackDraft` удерживает его после сетевых ошибок до успешного ответа с совпадающим question ID и dialogue ID. Общий `completeBackDraft` вызывается и после navigate, и после явного Retry. Существующий, в том числе намеренно пустой, cache не затирается. Просмотрены wiring и два новых теста повторных ошибок; они проходят. По сообщению parent фактический Chrome-проход с двумя подряд сетевыми отказами и успешным третьим Back вернул точные слова, planner/picker/paid=0; рецензент сам браузером не управлял. Свидетельство parent: `browser/back-after-two-network-errors.png`.

## Остальные проверенные границы

- Нейтральный ответ сериализуется с пустыми text/selected; прежние собственные слова остаются черновиком и не отправляются скрыто.
- Ранний переход к пониманию не обходит набранный, выбранный или явно нейтральный ответ. Проверены disabled UI и повторная проверка в navigate.
- Черновик редактора условий привязан к dialogue ID и точному baseline условий. Несвязанный rerender сохраняет его, новое подтверждённое состояние не подменяется старым редактором.
- Ctrl/Command+Enter отправляет ближайшую локальную форму; обычный Enter в текстовом поле не вызывает общий подбор. Busy/IME/dialog/defaultPrevented учитываются.
- «Моё» открывает локальные знакомые игры; переход в прежнюю историю оформлен отдельной явной ссылкой. Знакомство не равно постоянному исключению.
- Время показывается из проверенного metadata, цитата экранируется, интерфейс не обещает, что удобно прерваться. Снятие времени и undo факта отправляют отдельные бесплатные actions; API самопроизвольно не вызывается.
- Перенос UI-отзывов касается retained IDs; новое название не получает чужой draft/выбор. Основную shared feedback реализацию рецензент писал сам, поэтому данный документ не заменяет её независимое review.
