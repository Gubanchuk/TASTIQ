# Игровой путь: проверка UI 01.11.2026

Область: `/pick/game/`, исходники интерфейса и локальных черновиков. Нейтральный Native Utility сохранён. В этой подзадаче браузер, сервер и платные API не запускались; живой просмотр выполняет основной агент. Анализ кода не заменяет наблюдение в браузере и оценку человеком.

## Подтверждённые проблемы и исправления первой партии

1. **Свои слова и нейтральный ответ.** Прежний обработчик сохранял введённый текст после «Неважно», отправлял одновременно `kind: indifferent` и старый `text`. Ядро соединяет их в один ответ; это оставляло модели противоречивое сообщение. Теперь нейтральный выбор временно выключает прежние слова и карточки, явно показывает отправляемый ответ, отправляет пустые `text`/`selected`. Черновик можно вернуть отдельной кнопкой или повторным нажатием той же нейтральной кнопки. Случай воспроизведён RED на извлечённых прежних обработчиках: 2 из 5 тестов не прошли; после изменения 5 из 5 прошли.
2. **Переход к пониманию игнорировал текущий ответ.** `review` сохранял текущий текст только как локальный черновик и отправлял серверу переход без этого ответа. Затем результат мог строиться по прежнему желанию. Теперь при непустом тексте, выбранном варианте или явном нейтральном ответе ранний переход недоступен; видна подсказка отправить ответ через «Дальше». Защитная проверка также стоит перед навигацией. Дополнительных автоматических запросов нет.
3. **Несохранённые условия пропадали.** Редактор условий заново строился из серверного контекста после локального изменения памяти игр. Теперь черновик условий хранится через существующий `client.saveDraft('__context')`, связан с ID разговора и исходной платформой/компанией/числом игроков. Другой разговор, подтверждённое изменение условий, повреждённый или невозможный черновик не применяют старые значения.
4. **Клавиатурный путь расходился с DESIGN.md.** Добавлены Enter вне элементов управления и Ctrl/⌘+Enter; IME, ожидание и открытый dialog блокируют сокращение. Сочетание внутри формы поправки, условий или отзыва отправляет именно эту форму, а не основной подбор по старому запросу. Обычный Enter в многострочном поле сохраняет перенос строки.
5. **«Моё» вело в другую память.** Заголовочная кнопка теперь открывает знакомые игры в текущем разговоре. Внутри есть явно подписанная ссылка «История выборов и вечеров» к прежнему экрану. Память знакомства и прежняя библиотека не объявлены одним хранилищем.
6. **Малые цели касания и неточные статусы.** Верхние элементы навигации и нейтральные ответы получили минимальную высоту 44 px. Статус различает бесплатную отметку, поиск замены, восстановление и подбор; отметка больше не выглядит как новый поиск рекомендаций.
7. **Фокус и курсор внутри отзыва.** У поля заметки и select причины не было `id`, `data-focus` или `data-fk`; после `refreshFeedback` восстановить их фокус было невозможно. Теперь идентичность поля связана с ID игры и именем поля; textarea сохраняет диапазон выделения, его направление и внутреннюю прокрутку. У select редактора условий появились стабильные ID. Непрофильные события localStorage больше не перерисовывают отзывы. RED дополнительного теста показал сброс позиции 4→0; после изменения тест проходит.
8. **Свободный ответ на первом экране телефона был закрыт панелью действий.** Основной агент подтвердил Chrome390×705: textarea начиналась на601.6px и заканчивалась на697.6px, панель начиналась на638px; почти всё поле находилось ниже доступной области, нейтральные ответы — ещё ниже. Baseline: `../browser/initial-before-mobile.png`. По согласованной правке только у `direction` собственный ответ и нейтральные кнопки стоят перед 12 направлениями; ниже видна подпись «Или выбери направление». Остальные вопросы не переставлялись; ввод не стал обязательным.
9. **Применение условий также могло оставить неотправленный ответ позади.** Этот переход передан исполнителю ядра: теперь при редактировании условий во время активного адаптивного вопроса сохраняется его ID и экран, следующий явный ответ планируется уже с новыми условиями. По сообщению исполнителя client→service тест проверил бесплатное сохранение group3→solo с сохранением черновика и ровно один planner при следующей отправке. UI после принятого изменения показывает «Условия изменены. Проверь ответ на этот вопрос перед отправкой». При изменении условий из результата или проверки понимания прежний переход к проверке сохранён. Живое подтверждение этого перехода остаётся у основного агента.

## Оставшиеся вопросы проверки

- Отмена зависшего сетевого запроса относится к общему клиенту. В `src/ai/config.js` задан timeout45 секунд, OpenAI transport использует `AbortSignal.timeout`; общий браузерный transport отдельного таймера не имеет. UI не добавляет обещание отменить уже отправленную генерацию; контракт отмены пока не менялся.
- Неоднозначные/неразрешённые названия ожидают подтверждённую серверную схему. UI не выдумывает поля ответа и причины неопределённости.
- История исходников: предыдущие проверки знакомства и отзывы находятся в `test/feedback-view-state.test.js` и документах реализации знакомых игр; их результаты не выдаются за живую оценку текущего ответа.

## Фаза 2: время на сегодня и фокус заголовка

Контракт согласован с ядром: `screen.sessionTime` — `null` либо `{minutes,sourceId,quote}`; `remove_time` — бесплатное явное действие, сохраняющее текущий вопрос/черновик. UI не разбирает числа из сводки самостоятельно.

- Чип «На сегодня: N мин» виден в сводке и на проверке понимания; рядом «Убрать ограничение времени». Исходная дословная цитата доступна в уже существующих подробностях запроса.
- При отсутствии или повреждении метаданных чип и пустая строка доказательства не выводятся. UI не объявляет длительность игры проверенной и не обещает возможность прерваться.
- У нового экрана фокус получает `h1` с `tabindex=-1`, согласно DESIGN.md. Локальные пометки/замены сохраняют прежнюю логику фокуса, без анимаций входа.
- `test/time-budget-view.test.js`: RED2/3 → GREEN3/3. После интеграции 18/18 в наборе time-budget-view, answer-view-state, feedback-view-state и conversation-view; `node --check` успешен.
- Для браузерного подтверждения: сформированный сервером бюджет времени → чип/цитата → бесплатное удаление → прежний вопрос и черновик остаются. Проверка реальной вместимости игрового сеанса по-прежнему не доказана тестами UI.

После согласования контракта ядра добавлена одна второстепенная кнопка «Отменить удаление» в панели действий, только когда `screen.canUndoFactRemoval` истинен. Она отправляет бесплатное `undo_fact_removal`. Исчезнувшая кнопка «Убрать» переводит фокус на отмену; после отмены UI старается вернуть фокус восстановленному пункту, при reload — заголовку подробностей. Дополнительная основная кнопка или собственный несовместимый snapshot UI не создаются. Перенос отзывов не выдумывается: используются прежние подтверждённые правила `feedbackCarry` и сохранённая точная выдача.

## Фаза 2: черновик привязан к конкретному экземпляру вопроса

У AI-вопроса `id` обозначает тему. Ядро допускает повтор той же темы после «Ничего из этого» или поправки. Старый UI использовал только `id`: повтор мог получить старые слова, варианты или уже нажатую нейтральную кнопку. Даже неизменные заголовок/варианты не означают тот же экземпляр после принятого ответа.

Новый ключ `question.v3` содержит ID разговора, ID последней действующей поправки, смысловой отпечаток вопроса (`id`, заголовок, возможность нескольких/своих ответов, пары ID/подписей вариантов) и число уже принятых вопросов с тем же отпечатком после этой поправки. Перестановка вариантов не меняет смысл; изменение подписи меняет. `Back` удаляет принятый turn и возвращает прежний ключ; свободное изменение условий не увеличивает счётчик. Ключ экрана использует тот же экземпляр, поэтому повтор получает правильный новый фокус заголовка. Эпоха поправки закрывает отдельно найденный ревьюером случай: прежний вопрос ещё не был отвечен, цель явно исправлена, модель вернула тот же общий вопрос — прежние неотправленные слова не должны автоматически стать ответом на новую цель.

Миграция относится только к существующим черновикам `/pick/game/`, не к прежнему `/pick/`. Она выполняется один раз для разговора, не удаляет старые ключи `id`/`question.v2` и не перезаписывает непустые новые черновики:

- Очевидно старый черновик, совпавший с последним принятым ответом той же темы (сравнение слов без лишних пробелов, ID вариантов и вида ответа), относится к прежнему экземпляру; повтор начинает пустым.
- Текущие слова, отличающиеся от принятого ответа, сохраняются на текущем вопросе. Это сознательная консервативная граница: у старого ключа нет метаданных экземпляра, поэтому неоднозначный текст не выбрасывается.
- На review/result старые приостановленные слова сохраняются у последнего известного вопроса, чтобы вернуть их через Back. Принятые turn также дают восстановимые черновики прошлых экземпляров.
- Маркер миграции хранится тем же существующим клиентом; shared-client не менялся. Новые ответы уже используют полноценный ключ, включая пустой нейтральный повтор.
- При разовом переходе V2→V3 текущие уже сохранённые собственные слова консервативно копируются в текущий экземпляр: по старому ключу нельзя доказать, набраны они до исторической поправки или после. Следующая **новая явная** поправка в работающем UI получает другой ключ без повторной миграции. Прежний текст остаётся в старом ключе и возвращается при восстановлении старой эпохи. Это сохраняет текущий незавершённый запрос владельца, не перенося его автоматически в будущую цель.

Дополнительно закрыт Back после отправки поправки из отдельного редактора: у такого ответа раньше не создавался вопросный черновик. После успешного Back UI берёт удалённый turn и восстанавливает его текст/ID вариантов/вид ответа только при совпадении ID возвращённого вопроса и отсутствии кэша. Существующий черновик, в том числе намеренно пустой, имеет приоритет; context→Back с другим ID не подменяет неотправленный ответ. Значения проходят существующий `client.saveDraft` с лимитом1600; поле и выбранные варианты обновляются без новой перерисовки всего экрана.

`test/question-drafts.test.js`: RED6/7 на прежнем ключе по `id` → GREEN8/8; затем отдельный RED незаконченного вопроса после явной поправки → GREEN10/10; RED2 новых случаев Back → GREEN12/12. Проверены одинаковый повтор после none, изменённый вопрос, изменённые варианты, Back, context, reload, разные разговоры, новая эпоха поправки и сохранность старых собственных слов при миграции.

Позднее проверен ещё один фактический путь: Back не дошёл по сети, затем пользователь нажал «Повторить». Descriptor удалённого turn теперь сохраняется через неуспешные попытки, а один и тот же обработчик восстановления вызывается после успешного Back и явного Retry. Другой разговор, другой возвращённый вопрос, context-resume и существующий пустой/непустой кэш не получают чужой текст. RED1 → GREEN14/14 тестов черновиков; последний общий UI-набор 32/32, `node --check` успешен. Descriptor не запускает повтор автоматически и не меняет серверный контракт.
