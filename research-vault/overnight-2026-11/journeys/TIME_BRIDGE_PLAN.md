# Время сегодняшней сессии: минимальный план второй фазы

Статус: план реализован после отдельного Phase2 GO родительского агента; итог — `PHASE2_RESULTS.md`. Ниже сохранён согласованный план до реализации. Нового обязательного вопроса, регулярных API-вызовов или изменения каталога нет.

## Данные и смысл

Полный снимок state/proposal получает nullable поле:

```js
sessionTime: { minutes: 30, sourceId: 'conversation:7', quote: 'Сегодня есть 30 минут' }
```

Отсутствующее поле старого v1 считается `null`. Схема нового ответа модели требует поле с объектом либо `null`; снимок интерпретации целиком заменяет предыдущее поле. `sessionTime` означает доступное время **сегодняшней сессии**, не часы полного прохождения, прошлый опыт, желаемую общую длину игры или предположение о том, удобно ли прерываться.

Точный источник и цитата проверяются до применения всего предложения. Возраст источника определяется действующими/superseded репликами и retractions, а не номером последнего ответа: ранее названные сегодняшние 30 минут могут оставаться действующими после вопроса о жанре. Цитата — точный непрерывный фрагмент действующего `answer`; не перефразировать её и не брать слова из вопроса вместо ответа человека.

Целое `minutes` находится в диапазоне **5–1440**. Число обязано совпадать с детерминированно разобранной длительностью цитаты. Предложение `minutes:45, quote:'Сегодня есть 30 минут'` отклоняется атомарно; при этой ошибке нельзя принять другие новые факты и перейти к результату.

## Детерминированная проверка длительности

Отдельная чистая функция разбирает ограниченный набор явных форм без модели и нечёткого сопоставления:

- `30 минут`, `30 мин`, `30m`, `30 min` → 30;
- `полчаса` → 30;
- `час`, `1 час`, `1h` → 60;
- `1 час 30 минут`, `1h 30m` → 90; минутная часть составной записи 0–59;
- при необходимости `полтора часа` → 90 как отдельная явная форма.

Проверка не равна извлечению любой цифры из ответа. Принимать явную длительность в конструкции текущей доступности/сессии: «сегодня есть…», «у меня есть…», «могу поиграть…», «на одну сессию…». Короткий ответ `полчаса` допустим только в ответ на вопрос явно о доступном сегодня времени; тип такого вопроса должен быть передан явно либо определён узким проверенным контрактом, а не произвольной догадкой из ID. Если этот контракт нельзя надёжно установить, поле остаётся `null` и время можно сохранить как непроверенный смысл в сводке.

Не принимать общий срок прохождения/историю (`прошёл за 10 часов`, `на всю игру часов 30`, `раньше играл по часу`), отрицание наличия времени, неизвестность (`не знаю сколько`), предположение (`может, полчаса`), условие (`если останется полчаса`), диапазон (`30–60 минут`, `от получаса до часа`) и несколько конкурирующих величин без явного исправления. Такие ответы могут остаться в тексте/uncertainties; они не должны незаметно создавать жёсткий бюджет. Верхние/нижние границы вроде «не больше часа» первоначально тоже не преобразовывать в точное значение без отдельной согласованной семантики.

Если фраза непонятна ограниченному парсеру, валидатор отклоняет предложенный числовой бюджет и сохраняет честную неопределённость; не добавлять бесконечные вопросы или автоматически превращать отказ парсера в запрет длинных игр.

## Изменение, снятие и сохранённые состояния

1. `remove_time` бесплатно устанавливает `sessionTime:null` и добавляет отдельную retraction `{kind:'session_time',sourceId,quote}`. Для времени блокируется повторное применение **того же источника**, даже с иной подцитатой. Это предотвращает возрождение снятого ограничения.
2. Временная retraction не снимает другие пожелания из той же реплики. Существующий guard обычных фактов не должен трактовать её как отзыв жанра/механики из той же цитаты.
3. Новая явная поправка создаёт новый источник и может задать другое время. Старое время на этапе `correct` снимается до нового ответа модели; неподтверждённый старый лимит не действует при временной недоступности planner.
4. `back` удаляет время, если удалён его источник; источник, ставший superseded после смены условий, тоже больше не подходит. Обычный дополнительный ответ не стирает подтверждённое время до следующего полного снимка.
5. `restart` сбрасывает время. Undo замены карточек сохраняет действующий запрос и время. Восстановление предыдущего подбора возвращает его время, доказательство и retractions бесплатно.
6. При чтении сохранённого поля перепроверить форму, действующий источник, точную цитату, соответствие значения и retraction. Непроверяемый сохранённый лимит снять, добавив видимую неопределённость «Сохранённое время не удалось подтвердить» перед прочими uncertainties; весь разговор из-за одного такого поля не сбрасывать. Старый v1 без поля восстанавливается без ошибок и без такого предупреждения. Новое непроверенное предложение модели по-прежнему отклоняется атомарно.

## Связь с движком, UI и отзывами

- Адаптер задаёт `legacy.session.minutes` напрямую. `sessionOf` уже переносит поля `state.session`; не создавать искусственный старый `confirmedIntent`, где sourceText подменён сводкой и оригинальная цитата перестаёт совпадать.
- В `legacy.conversation` сохраняется объект `sessionTime` с доказательством для финального picker. В prompt число и исходные слова должны оставаться условием текущей сессии, не выводом о длине всей игры.
- `feasibilityOf` уже умеет показать для игр `minutes/unknown`: «не проверено, удобно ли прерваться через N мин». Не превращать это в обещание, что любая рекомендованная игра укладывается в бюджет; не фильтровать игру по общим часам прохождения.
- UI показывает отдельную заметную строку/чип «Сегодня N мин» со свободным снятием, без нового обязательного вопроса. `remove_time` не уничтожает ещё не отправленный ответ текущего вопроса и не вызывает planner/picker.
- Parent меняет shared feedback: `context.minutes` учитывает проверенный `state.session.minutes` при отсутствии старого confirmed intent. Разные бюджеты времени должны создавать разные контексты вечера; перенос отзывов не допускается между несовпадающими контекстами.

## Работы и владение файлами

1. **played_logic: core + новый focused test.** Сначала RED для числового согласования, смысла времени, жизненного цикла, адаптера и `remove_time`; затем `src/core/conversation.js` и небольшой чистый валидатор времени при необходимости. Не трогать чужие существующие тесты.
2. **history_trace: AI schema/input/instructions + его тесты.** Nullable root field, исходные source/quote, полноценная замена снимка, запрет путать прошлое/полное прохождение/условие с сегодняшним временем. Не вызывать платный API. Валидатор остаётся в core; AI только предлагает.
3. **ux_audit: UI.** Отображение бюджета и `remove_time`, отсутствие обязательного вопроса, сохранность draft/фокуса при снятии. Транспортный action согласовать до правок.
4. **Parent: shared feedback + интеграция.** Перенос минут в контекст отзывов и соответствующие тесты; заморозка первой фазы перед параллельной второй; общий бесплатный suite, независимая проверка связей, затем только согласованный адресный настоящий вызов.

## Обязательные тесты перед GREEN

| Случай | Независимое ожидаемое поведение |
|---|---|
| «Сегодня есть 30 минут», `minutes:30` | Поле принимается; session.minutes 30; feasibility предупреждает о непроверенном прерывании |
| «Могу поиграть полчаса», `minutes:30` | То же числовое значение без обязательной цифры в цитате |
| «Сегодня могу поиграть 1h 30m», `minutes:90` | Точное сложение единиц |
| Цитата о 30 мин, `minutes:45` | Атомарный отказ предложения, без новых фактов/вопроса |
| «прошёл за 10 часов» / «на всю игру 30 часов» | sessionTime null; никакого бюджета 600/1800 мин |
| Неизвестность, отрицание, диапазон, условие | sessionTime null; не жёсткое ограничение |
| `minutes:4` / `1441` / нецелое / чужая цитата / superseded source | Не становится действующим временем |
| Новая поправка с 20 мин вместо 30 | Только новый лимит и его новый источник |
| `remove_time` и попытка вернуть время с тем же sourceId | Снятое не восстанавливается; другие факты источника сохраняются |
| Back/снятый источник/перезапуск/старый v1 | Корректный сброс либо бесплатное безопасное восстановление |
| Снятие времени при набранном текущем ответе | Тот же вопрос и видимый draft, API 0 |
| Feedback 30 мин против 60 мин | Разные контексты; отзывы не переносятся автоматически |

При первой реализации запускать чистые/core/schema/feedback тесты бесплатно. Проверку настоящей моделью назначает только parent после GREEN; она проверяет фактический новый контракт, а не отменяет проваленные детерминированные проверки.
