## Требуют исправления

1. **P2 — переключение выбора/старта теряет клавиатурный фокус.** `app.js:141–152` сохраняет и восстанавливает `data-fk` при полной перерисовке feedback. В `evening-view.js:10` ключ включает значение: `evening-choose:run:card:on` после выбора заменяется на `...:off`; аналогично start. Старого элемента уже нет, fallback отсутствует. После Enter/Space фокус оказывается вне управления карточкой. Нужен стабильный идентификатор фокуса для переключателей action/run/card либо явное восстановление на соответствующую новую кнопку. Проверить choose и start с клавиатуры, включая альтернативу.

2. **P2 — незаписанный отзыв на оставленной игре исчезает при замене соседней.** `feedbackDrafts` и `feedbackOpen` привязаны к `runId:cardId`, а `observeResult()` (`app.js:160–163`) переключает activeEvening на новый run без переноса этих UI-данных. Submitted ответы копируются, но введённый комментарий/причина остаются только под старым ключом и пропадают из новой формы. Переносить черновик и раскрытие только для пересечения сохранённых ID, не для новых карточек. Проверить набор текста без «Сохранить отзыв» → замена другой игры → текст и причина сохранены у прежнего ID.

3. **P2 — успешный повтор familiar-action не обновляет локальную память знакомства.** `history.remember` (`app.js:211`) выполняется только в callback исходного familiar-click. При сетевой ошибке он уже завершается с null. Generic «Повторить» (`app.js:222`) исполняет действие conversation успешно, но не повторяет запись в game-history. Получается отмеченная карточка без записи в «Знакомых играх». Согласовывать локальную память после успешного retry на основании именно явных marked/keep; не добавлять оценку и постоянный запрет. Проверить потерянный ответ mark/keep → retry → запись списка → reload.

4. **P2 — undo замены возвращает устаревший отзыв об оставленной игре.** В `evening-feedback.js:115` prior по ключу возвращается до inheritance. После замены можно изменить выбор/отзыв сохранённой игры, а «Вернуть предыдущие варианты» вернёт её старый response из original run. Текущий тест `evening-feedback.test.js:161` закрепляет проблему: после next.game2 chosen=false undo снова выдаёт chosen=true. Отмена состава выдачи не должна отменять последующее мнение о неизменённом ID. На явном переходе undo нужен перенос актуального response сохранённых игр; при повторном observe/reload нельзя повторно перетирать более новые ответы старым source. Возвращаемым карточкам, которые отсутствовали в новой выдаче, следует сохранить собственные прежние ответы.

## Что проверено без замечаний

- Отдельная память знакомства не импортирует legacy library и не превращает played в rating/block. Отдельные ключи игр не перезаписывают несвязанные записи других вкладок; отказ storage переключает store в память текущего окна.
- Conversation client сохраняет previous snapshot и drafts перед restart, восстанавливает их actionless, не начинает planner/picker на reload. generation/id/revision защищают от позднего ответа, network retry повторяет исходный запрос, server retry использует подтверждённый revision.
- Inheritance submitted feedback ограничен dialogue/domain/context и пересечением ID. Новая карточка не получает chosen/start/outcome старой; транзакция видит последнее сохранённое мнение источника, payload не отправляет исходное пожелание или AI-объяснение.
- Новые отметки не создают лишний feedback run при неизменной выдаче; прежние непомеченные карточки остаются доступными. Ошибка и partial replacement не скрываются за сообщением полного успеха.

После исправлений достаточно адресной проверки четырёх сценариев; весь первоначальный UX-проход повторять не требуется.

## Адресная повторная проверка после исправлений

Повторный вердикт: **Pass в проверенном объёме кода и офлайн-тестов**. Все четыре исходных P2 закрыты; исходные записи выше оставлены как история проверки.

1. `preserveView()` теперь дополнительно сохраняет стабильную пару action/cardId для choose/start, а `restoreView()` использует её после смены on/off или run. Fit/outcome сохраняют точное значение кнопки. У прежнего переключателя есть достижимый фокус после перерисовки.
2. Новый `pick/game/feedback-view-state.js` переносит черновики, раскрытие feedback и outcome только по `feedbackCarry.retainedIds`. Явный переход использует overwrite: текущий пустой текст/закрытое состояние учитываются, старый destination draft после отправки удаляется; состояние заменённых карточек не переносится.
3. `pendingFamiliar` хранит конкретный явный mark/keep и dialogueId через сетевой сбой. И обычный успешный ответ, и успешный generic retry вызывают `rememberAcceptedFamiliar`; helper принимает только подтверждённую отметку того же разговора. Постоянная синхронизация всех facts не добавлена, удалённая пользователем история не восстанавливается при простом render/reload.
4. UI передаёт `carryIntoExisting:true` только при явном feedbackCarry. Store обновляет ответы совпадающих retained ID даже в прежнем target run, сохраняя собственные отзывы вернувшихся карточек. Сохранённый carryFrom(sourceId,revision) делает этот перенос однократным: повторный observe/reload не отменяет более новое редактирование target. Старое поведение обычного exact-prior observe остаётся отдельным default и больше не используется для явного undo UI.
