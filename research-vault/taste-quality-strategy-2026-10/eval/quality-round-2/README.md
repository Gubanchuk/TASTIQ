# Проверка качества подбора, раунд 2

31.10.2026. [Итог](../../../../docs/QUALITY_ROUND_2_2026-10-31.md), [план и журнал](../../../../docs/superpowers/plans/2026-10-31-quality-round-2.md).

## Протокол

1. `intent-cases.frozen.json`: 20 авторских случаев, критерии сохранены до ответов. 12 диагностических / 8 отложенных. Критерии проверяют явные желания, недопустимые выводы, минуты и уточнение; не перечисляют все допустимые/недопустимые признаки и не являются человеческой оценкой качества.
2. `comparison-cases.frozen.json`: восемь состояний из session-v1, одинаковый профиль, подтверждённые слова и практические ограничения в обоих способах. Игры 4, мультфильмы 2, сериалы 2; кино в сравнении подборов нет. Исходные model/effort одинаковые: gpt-6.1-sol / low. Порядок вызова способов чередуется. По одному ответу на состояние, без статистической значимости.
3. Hybrid получает 40 кандидатов с тегами и до двух собственных названий. Direct получает тот же `describePerson`, называет четыре тайтла без shortlist, все четыре можно разрешить в каталоге. Это сравнение подходов, не изоляция одной строки промпта. Direct не получает описание всех кандидатов, поэтому дешевле. Оба проходят один resolver и одни сита. Engine-fill учитывается отдельно, не как выбор модели. Неудачный подбор целиком также должен учитываться как неудача, а не исчезать из знаменателя.
4. `intent-scope-cases.frozen.json`: отдельные восемь случаев после ручной находки d05, до правки. 4 диагностических / 4 отложенных. Исходные 20 критериев не переписаны. V2 показала регрессию и не оставлена. V3 проверена на всех 28 исходных формулировках.
5. `resolver-replay.json`: те же 16 сохранённых Responses, ноль новых API. Проверяется точное совпадение тела запроса; изменилось только разрешение одного проверенного года оригинального релиза.

## Что лежит в файлах

- `budget.json` — общий потолок $5, прежние $0.7161141 / 47 успешных обращений и все новые запросы/ответы без заголовков/ключа. Тарифы `src/ai/usage.js`; usage, cached input и output разделены, reasoning повторно не прибавляется. Это расчёт, не сверка счёта провайдера.
- `comparison-details.json` — первоначальные 16 подборов, включая состояние, полученные названия, reason/caveat, fills и shortlist.
- `analysis.json` — воспроизводимые счётчики, стоимость двух подходов и причины, по которым собственное название не разрешилось. `no-exact-title-match` означает отсутствие точного совпадения в текущем resolver, не доказанное отсутствие любой альтернативной записи/алиаса.
- `intent-v1-*`, `scope-v1-*`, `scope-v2-dev`, `scope-v3-*`, `intent-v3-*` — все результаты, включая неудачные версии. `assessment.pass` означает только перечисленные в fixture условия.
- `review-queue.json` / `review-key.private.json` — слепая очередь первоначального сравнения и отдельный ключ происхождения. `review-current-*` — очередь после resolver replay. Не смешивать версии. Человеческих оценок сейчас **0**; никто не ставил модели метки за человека.
- `human-current-summary.json` — human acceptance остаётся `null`, не 0%.

## Воспроизведение без оплаты

```powershell
npm test
node test/server-smoke.mjs
node --max-old-space-size=8192 src/stand/quality-replay.js
node --max-old-space-size=8192 src/stand/quality-analysis.js
```

Для реальных новых экспериментов есть `src/stand/quality-round.js --paid --phase ...`. Существующие отчёты запрещено перезаписывать: завершённая партия повторно не запускается, частичная требует разбора receipts. Не удалять файлы для обхода защиты. Журнал блокирует конкурентный запуск, резервирует расход до запроса, повторяет завершённый ID только из сохранённого ответа и останавливается при неизвестном usage/транспортном результате. Исходный лимит новой партии — $2 в пределах общего $5; это предохранитель стенда, не серверный денежный лимит всех пользователей.

Подробные оценки человека можно записать в копию нужной слепой очереди и посчитать существующим `src/stand/session-eval.js --reviews ... --key ... --out ...`, сохраняя соответствующий ключ отдельно.
