# Проверка сегодняшнего запроса

31.10.2026. Команда: `npm run eval:session`. Новых сетевых или оплаченных вызовов нет.

Стенд берёт устойчивые ответы четырёх существующих синтетических персон и задаёт каждой два противоположных пожелания. Исходные персоны и их targets не изменяются. Интерпретации пожеланий в этом стенде написаны вручную: он проверяет передачу подтверждённого смысла через движок, а не качество разбора OpenAI и не удовлетворённость людей.

В каждом из восьми сценариев сравниваются два состояния одного профиля: слова сохранены без структурированной интерпретации; те же слова плюс подтверждённые wants/avoids. Остальные условия одинаковые. Считаются выборка кандидатов, вопросы, первая четвёрка, непроверенные практические условия. Изменение списка само по себе не означает улучшение.

- `mechanisms.json`: воспроизводимые механические результаты. Первое место изменилось в 2/8 сценариев относительно варианта без интерпретации. Игры — 4 сценария, мультфильмы — 2, сериалы — 2. Обычные фильмы покрыты отдельными regression/unit-тестами, живой оценкой пока не покрыты.
- `review-queue.json`: 42 карточки для человеческой оценки, без имени персоны, названия системы, позиции и рейтингов движка. Один тайтл в одном сценарии показывается оценщику один раз, даже если он есть в обоих вариантах. Контекст и устойчивые ответы сохранены, поскольку без них невозможно оценивать соответствие.
- `review-key.private.json`: связь карточек с вариантом и позицией. Оценщику этот файл не показывать.
- `human-summary.json`: пока все оценки отсутствуют; acceptance равен `null`, а не 0%. Человеческой приёмки не было.

## Как оценивать

В копии `review-queue.json` для знакомых тайтлов заполнить `judgment`:

- `accept`: стал бы смотреть/играть при таком запросе.
- `conditional`: только при указанном условии; записать его в `conditions`.
- `reject`: не соответствует; указать конкретную причину в `reason`.
- `unknown`: не знаешь тайтл или не хватает данных. Это не отказ.

`null` означает, что карточку ещё не оценивали. `started` и `afterUse` заполняются только по реальному началу и опыту, не по намерению и не от имени синтетического человека. Оценка незнакомого сценария сторонним человеком — экспертная пригодность, не личная удовлетворённость владельца приложения.

Для подсчёта:

```powershell
node src/stand/session-eval.js --reviews <путь-к-заполненной-копии> --key research-vault/taste-quality-strategy-2026-10/eval/session-v1/review-key.private.json --out <новая-папка-результата>
```

Доля безусловного принятия: accept / (accept + conditional + reject). Рядом всегда есть unknown, unreviewed и знаменатель decidable. Доля списков с хотя бы одним accept считается только по полностью оценённым спискам без unknown; число таких списков показано отдельно. Пропуски, ошибки генерации, неизвестные и подстановки движка не прячутся в общий процент. Поля model/fill/engine поддерживаются для будущего сравнения с AI; в этом бесплатном запуске все варианты от движка.

Текущий стенд не сравнивает новую архитектуру с простым AI-only подходом и не доказывает, что система стала лучше подбирать. Следующий замер — независимые оценки этих карточек и несколько реальных сессий, затем один изолированный эксперимент по найденным причинам отказа. Старые targets остаются отдельной регрессией (3/36, медиана ранга 7.5).
