## Изменение

Экспорт `aiConversation(catalog,state,{api,maxCostUsd})` соответствует интерфейсу плана. Один OpenAI Responses request одновременно предлагает полное понимание со свидетельствами и следующий вопрос либо предварительное review. Модель и effort берутся из существующего AI config. Нет внутренних повторов, рекомендаций, отдельного extraction-вызова, внешних фактов или изменения состояния.

Строгая JSON schema описывает все поля Proposal/Fact/Question, nullable поля, словарные feature ID, ограничения длины и числа элементов. Prompt разделяет историю и сегодняшний запрос, явно сохраняет neutral/conditional смыслы, несколько ответов, возможность продолжить начатую игру, поправки и retractions. Знакомые игры необязательны. В free модель управляет последовательностью; guided добавляет ограничения переходов к той же разговорной способности, данным, schema и model/effort.

Input включает точные активные turns, принятые facts, retractions, context, question, summary, uncertainties и определения features. Не включает profile/result. Ответы не обрезаются. Отказ до dispatch при >24 turns, >16 facts, >240000 UTF-8 байт input или недостаточном/невалидном конечном бюджете. Reserve считается существующим reserveCost; фактический учёт и общий ledger остаются транспортом вызывающей стороны. Output reserve6000 tokens ограничивает стоимость одного обращения; неполный ответ возвращает ошибку без повтора.

Usage/model/ms сохраняются при полученном ответе, включая отказ/неполный/неправильный JSON. Известный OpenAIError выводится существующим безопасным сообщением; неожиданные provider errors не раскрываются.

## Интеграция и пределы

Сервер должен передать нормализованное состояние и существующий budgetTransport, применить proposal атомарно через core, обработать ошибки без paid reload/retry, сохранить usage. В модуле только transport-level проверка верхней формы ответа; вложенные поля, точные quote/source, семантика и переходы проверяются ядром. Это намеренное разделение контрактов, без core imports.

Тесты проверяют формирование обращения и обработку ответов через offline transport. Они не доказывают, что настоящая модель соблюдёт смысловые инструкции, и не измеряют человеческую пригодность выбора. Нужны запланированные интеграционные/браузерные проверки и ограниченный живой прогон владельцем общего ledger.

## Дополнение интеграции: локально распознанные названия

По запросу root добавлена необязательная опция `knownGames=[]` в `aiConversation`: максимум12 записей `{id,name,ru?,year?}`. Root находит названия по исходным словам/поиску локально. AI input получает только эти identity-поля; любые переданные свойства каталога, предполагаемые симпатии или exposure удаляются. Более12 записей или неправильная форма не запускают transport. Исходные turns остаются целиком. Совокупный лимит240000 UTF-8 байт действует и на identity-контекст.

Prompt разрешает gameId только из knownGames и только для названия, подтверждённого source answer. Само упоминание или наличие в knownGames не означает played/liked/disliked или сегодняшнее желание: exposure и реакции требуют явных слов и цитаты. Core дополнительно проверяет ID, соответствие названию и свидетельство, как согласовано с root. Обновление интерфейса плана выполняет root.
