# TASTIQ: выбор интерфейсного направления

Поручение владельца 02.11: оживить сайт; разделить глобальную навигацию и действия подбора; заменить непонятное «Моё» библиотекой с фильтрами и обложками; обновить устаревший низ лендинга. Вопросы игры в целом устраивают. Позднее владелец отдельно попросил показать мини-макеты для выбора направления. До выбора перенос в основной интерфейс не выполняется.

Подтверждено через structured question: смешанное оформление — тёмный фон, светлые тёплые поверхности, обложки и один акцент. Этапы подбора должны выглядеть индикатором прогресса, поскольку они не являются кнопками. «Назад» — отдельное действие.

Кликабельное сравнение `/design/`: три направления, четыре экрана в каждом — вопрос, выдача, библиотека, лендинг. Обложки и названия взяты из текущего каталога; заполнение библиотеки и диалог демонстрационные и подписаны. Кнопки/фильтры/поиск/сохранение/замена работают только в памяти макета. Приложение и журнал владельца не затрагиваются. Единственная отдельная запись localStorage — явно выбранное направление `tastiq.design-choice.v1`. Вызовов платного API нет.

## Direction contract

THESIS: выбор сегодняшнего занятия и возвращение к сохранённому — две понятные задачи; шаги — прогресс, действия называют свой результат.

OWN-WORLD: владелец выбрал смешанные поверхности. «Вечерняя программа» — тёмный хвойный фон, тёплая светлая карточка, светлый лимонный акцент, Onest и цветные обложки. «Крупный план» — синяя тёмная сцена с большим изображением и тёплыми светлыми служебными поверхностями. «Медиатека» — светлая рабочая область с постоянной тёмной навигацией.

STORY: желание → условия → уточнения → варианты; сохранение отдельно от знакомства и вкуса; библиотека содержит списки и фильтры по четырём разделам.

FIRST VIEWPORT: у первого варианта верхняя навигация по разделам, видимая библиотека, линейный прогресс, ведущая обложка слева в светлой карточке и отдельная тихая сводка. У второго картинка занимает сцену; у третьего навигация слева и светлое поле. Вопросы — один экран с inline Next. На телефоне сохраняются подписи и основной шаг.

FORM: собственный культурный ряд: личная коллекция; программа кинотеатра; вечерняя программа; музыкальный tracklist; журнальный гид; телевизионная сетка; каталог библиотеки. Concept seed `1aa68947` назначил позицию 3. Полноценный API roll получен после повторения с разрешённой сетью. Пользователь затем явно попросил собственные мини-макеты для сравнения: сравниваем три code-led направления, первое — назначенная вечерняя программа, третье — верхняя коллекционная идея. Не заменяем макеты сгенерированными картинками: установленное требование проекта — кликабельный сайт, нынешнее поручение — работающие мини-макеты.

FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance.

Здесь завершается только сравнение. Основной DESIGN.md описывает существующий сайт до принятия нового направления и не переписывается по невыбранным макетам. Документация сравнения хранится отдельно. Все исходные постеры остаются по прежним URL из каталогов; новых растров нет. Шрифт Onest self-hosted, SIL OFL: https://github.com/google/fonts/tree/main/ofl/onest.

## Проверка

Один пакет desktop/mobile по трём направлениям и ширина панели пользователя; клики вопрос → выдача → библиотека, сохранение/замена, поиск/фильтры, пустой список, возврат, Escape. После одной пакетной коррекции — подтверждение. Независимый finish review и документация. API до/после — тот же ledger, платных вызовов не требуется.
