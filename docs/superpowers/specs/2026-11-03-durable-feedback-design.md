# Отзыв после каждого подбора и постоянная память

Владелец прямо заменил ручной сбор: в конце каждой выдачи спрашивать, как прошло и что не так; сохранять в базу для собственного анализа и улучшения следующих рекомендаций. Отдельные сообщения тестировщикам не нужны. Модель не переобучает свои веса от записи в таблицу: реализация использует отзывы этого браузера как ограниченный исторический контекст существующего pick-вызова. Общие изменения качества принимаются по анализу базы; непроверенный отзыв не становится новым системным правилом для всех.

## Пользовательский путь

В конце modern game/film/series/cartoon result — один встроенный блок «Как тебе подбор?»: «Нашёл своё», «Есть близкие варианты», «Ничего не подошло», необязательная причина и свои слова, явная отправка. Поле текста не отправляется до submit. Точный запрос/показанные варианты прикладываются после явного отправления, с понятной подписью об этом. Текущий бренд, карточки и существующие fit/choice/start/outcome сохраняются.

Отзыв привязан к конкретному показанному списку. More создаёт отдельный список; неудача/отрисовка/reload не дублируют его; undo возвращает его прежний отзыв. Черновик и очередь переживают reload. Отправленный статус появляется только после надёжного ACK. Изменение текста во время медленного ACK остаётся новой pending-ревизией.

## Данные и сервер

Расширить существующий version1 feedback-run необязательным selectionReview. Старый формат и карточные оценки совместимы. Общая IndexedDB транзакция/очередь уже решают гонки вкладок и поздние ACK — использовать их. Новое поле содержит verdict, issue, note, requestSummary и selectionCopyText текущего snapshot; не включает библиотеку/черновики/старые undo-выдачи. Server проверяет размер/структуру/каталожные ID и канонические названия.

Все `/api/feedback` события сохраняются сервером в Supabase через закрытый RPC: append-only `(run_id, revision)`, одинаковый повтор idempotent, другой payload той же ревизии — conflict. Устаревшая доставка не затирает новую. RLS и отсутствие anon/authenticated table/RPC grants; секрет только на сервере. QA не пишет в пользовательскую базу. При отказе БД — не ACK, клиент сохраняет очередь. На Vercel отсутствие настройки означает503, а не ложный успех временного файла. Локальный журнал остаётся резервом локальной разработки. 04.11 владелец выбрал existing Family и tastiq_ names. Только additive feedback objects; scoped TASTIQ Edge ingestion token вместо общего Family key. Новый платный ресурс не создаётся.

## Учёт отзывов

До6 явных отзывов этого браузера, только того же раздела, ограниченные тексты/проверенные ID. Исторический контекст подаётся данными в существующий pick; новый API-вызов на отзыв не делается. Сегодняшний запрос/исправления/строгие ограничения сильнее старого отзыва. «Не начал», знакомство, сохранение и неизвестная оценка не равны отрицательному вкусу. Сырые отзывы не исполняются как инструкции. Не менять каталоги/ranking/политику на основе одного комментария.

Нужна возможность отключить учёт своих отзывов без удаления аналитической записи. Диалог и имя пользователя не публикуются; публичного чтения базы нет. Для владельца — запросы/сводка последней ревизии по списку, причины отказа и отзывы после начала отдельно. Сырые данные не коммитить.
