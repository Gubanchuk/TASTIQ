# Убрать препятствия до и после выдачи

**Цель:** общий вход с главной открывает выбор раздела; первый вопрос доступен без ожидания сервера; желание и ограничения выбираются кнопками; после выдачи можно продолжить тот же запрос.

**Основание:** владелец согласился с обратной связью на трёх приложенных снимках и отдельно потребовал убрать прокрутку лендинга при начале подбора. Оформление и бренд сохраняются. Реализация в текущем checkout без публикации и платных API-тестов.

**Устройство:** общие чистые начальные state/question используются сервером и клиентом; существующие сохранения восстанавливаются прежним бесплатным путём. Новый /pick/start/ — статическая страница выбора четырёх разделов. Действие more использует действующие ограничения/замену, хранит показанные ID отдельно от знакомства и не меняет вкус.

- [x] Общий вход и мгновенный первый вопрос: создать shared/conversation-entry.js, подключить core constructors и opt-in localStart клиента, /pick/start/, изменить общие ссылки главной. Проверить совпадение локального и серверного начала, отсутствие запроса при новом старте, восстановление черновика.
- [x] Общая форма вопроса: сначала варианты желания, отдельно жанры и ограничения, собственный текст необязателен. Нейтральные ответы после вариантов; «Ни один вариант не подходит» только при наличии вариантов. Проверить отрицательный смысл ограничений и сохранение черновиков.
- [x] Продолжение: more для game/media, исключение всех ранее показанных произведений и их изданий, прежние варианты при ошибке, retry/undo, честное сообщение об исчерпании каталога. Проверить несколько партий без повторов, отсутствие знакомства/изменения вкуса, budget/access guards.
- [x] Проверка: unit, HTTP stub, build; native браузер desktop/mobile через изолированный AI-off/stub сервер, включая выбор раздела, ответ без текста и more/error/undo. Обновить CODEX_CONTEXT и память, указать фактические ограничения проверки.

Риски проверки: сохранённый результат не должен запускать платный retry; more не должен отмечать человека знакомым с произведением; keep/другие издания не должны обходить исключение показанного; неполная новая партия не должна молча повторять старые карточки; холодный Node всё ещё может задерживать первый отправленный ответ, поэтому не обещаем нулевую сетевую задержку.
