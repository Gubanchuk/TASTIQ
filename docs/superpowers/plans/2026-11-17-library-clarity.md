# План: библиотека и названия действий

> Исполнение в текущем чате по поручению владельца. Использовать executing-plans; текущий checkout сохраняется, чужие изменения не отменять. Commit/push только после проверок, deploy отдельно.

**Цель:** человек отдельно находит сохранённое и понравившееся, понимает действия после подбора и не теряет отметки при навигации.

**Архитектура:** совместимые операции сохранения в library-store; чистая read-only проекция коллекции объединяет прежние записи, знакомство и отзывы; существующий library controller отображает новые представления и URL-состояние. Picker использует те же операции, отзыв о рекомендации остаётся отдельным.

**Стек:** существующие ES modules, HTML/CSS, node:test, локальный HTTP fixture, Chrome.

**Spec:** [library-clarity-design](../specs/2026-11-17-library-clarity-design.md).

## Ограничения и риски

- Сохранение, отношение, знакомство, выбор и feedback независимы. Чтение не пишет и не отправляет отзывы.
- Сохранить исходный envelope/unknown fields/историю и старые draft keys. Снятие сохранения не удаляет оценку.
- Положительный outcome виден в Понравилось, fit accept не является лайком. Конфликт истории не угадывать.
- Не менять AI/core/каталоги/DB. Только бесплатные подменные проходы. Не создавать новые production данные.
- Длинный список, мобильные фильтры, сброс, Back/reload, поздняя транзакция отзыва должны сохранить работу человека.
