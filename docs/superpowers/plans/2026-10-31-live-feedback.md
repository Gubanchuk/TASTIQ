# Реальная обратная связь по вечеру

> Исполнение: executing-plans, inline; один свежий финальный обзор. Коммиты не запрошены, используем текущий checkout и сохраняем план.

**Цель:** связать сегодняшний запрос и показанные варианты с отдельными ответами «подходит», «выбрал», «начал», «как прошло», чтобы следующий шаг качества опирался на реальные причины отказа.

**Архитектура:** браузер хранит версионированные снимки показанных подборов и текущие ответы, отправляет их отдельным валидируемым HTTP-маршрутом без вызова AI. Сервер пишет в существующий journal; отчёт выбирает последнюю ревизию каждого снимка, считает этапы и неизвестные ответы отдельно. UI использует существующие карточки, «Моё» и стили.

**Стек:** существующие ES modules, Node HTTP, localStorage, без зависимостей. **Spec:** описание ниже. Основание — команда пользователя «ну так погнали» после предложения перейти к реальным оценкам; дополнительные вопросы/подтверждения для этого среза не нужны.

## Описание и границы

- В деталях результата: явная кнопка «Выбираю на сегодня»; сохранить на будущее в «Моё» остаётся отдельным действием. Ссылка на магазин/IMDb и bookmark не означают выбор или запуск.
- Необязательный отзыв «Подходит на сегодня?» с accept/conditional/reject/unknown; причина (настроение, вкус, время, компания, доступность, уже знакомо, другое) и слова до 300 символов. Отзыв не меняет постоянный вкус и не вызывает новый AI-подбор.
- После явного выбора можно отметить начало; в «Моё → Вечера» — «понравилось / нормально / не зашло / не начал». «Не начал» не считается отказом от рекомендации; отсутствие ответа не равно отрицательной оценке. Ответ о впечатлении после знакомства подтверждает факт начала, но не выдумывает время начала.
- Диалог имеет стабильный browser-generated ID: back/reload сохраняют, успешный restart меняет. Снимок списка имеет отдельный run ID; один диалог может иметь несколько показанных списков. Отчёт показывает оба знаменателя.
- Сохраняется текущий контекст, ID/названия карточек, происхождение model/fill/engine, показанные объяснения, revision. Ответ относится к снимку, а не к будущему подбору той же игры.
- Доставка повторяемая и без потерь при временной недоступности сервера: локально хранится последняя неотправленная ревизия, retry при online/следующем визите. Дубликаты/старые ревизии не увеличивают статистику. После ошибки UI не обещает успешную отправку. Память ограничена 60 снимками, неотправленные не вытесняются.
- Новые отзывы отправляются без имени. В UI явно написано, что ответы сохраняются на устройстве и отправляются для улучшения подбора; старое обещание «всё только в браузере» ограничено библиотекой. Исходный свободный текст контекста хранится локально; сервер получает структурированные условия и ID подтверждённых признаков, а текст отзыва только после явной отправки пользователем.
- Не заполнять human labels моделью. Старые 53 слепые карточки сохраняются. Не менять веса, строгие фильтры и каталог без нового причинного доказательства. Выполнить read-only диагностику потерянных кандидатов; массовой разметки не делать.
- API-расход этой реализации $0: браузер с AI_ACCESS=off либо все AI-маршруты перехвачены, тестовый journal отдельно. Общий потолок $5, tracked upper $1.0515197 не сбрасывается.

## Проверяемые риски

1. Bookmark/seen/unknown не должны стать accept/choice/started — тест модели данных/метрик.
2. Перезагрузка, смена результата и диалога не смешивают вечера — тест store и client ID, browser.
3. Медленная/неудачная отправка и out-of-order retry не теряют новые ответы и не удваивают метрики — тест store/сводки.
4. Неправильные поля, чужой domain/id и HTML в отзыве — server validation и безопасный вывод, HTTP/browser.
5. Мобильный экран, доступность действий и фокус после ответа — browser 390/1440; нет платных запросов.

## Журнал

- Старт: 181 тест по предыдущему этапу, Git main без HEAD; индекс пользователя не тронут. Новых API-вызовов нет.
- Решение: сначала сделать путь получения реальной оценки; автоматический подбор не заменяет ответы человека. Цена ошибки: без оценок пока нельзя доказать рост удовлетворённости.
- Проверка до финального review: 191/191 тест; HTTP smoke PASS с подменой OpenAI. RED→GREEN поймали dotted feature IDs, ответ во время slow ACK и сохранение записей двух вкладок. Доставка теперь забирает свежие ревизии до 120 запросов за flush, останавливается на первой ошибке.
- Browser 1440×1000 / 390×844, AI_ACCESS=off, отдельный временный journal: bookmark не выбор; conditional/reason/text → chosen → started → not_started; HTML в тексте экранирован; вкус не изменился; offline → reload → online доставил последнюю ревизию; reload не создал снимок; restart отделил новый диалог. Paid requests 0.
- Ruling: формулировка приватности относится именно к отзыву: исходное пожелание к нему не прикладывается. Другие маршруты подбора уже обрабатывают пожелание — общее обещание «оно только в браузере» было бы неверным.
- Ruling: текущий checkout без HEAD, пользовательский индекс сохраняем; вместо git-range reviewer получает явный список новых/изменённых модулей. Коммитов и новых worktree не создаём.
- Финальный review: один GPT-6 Astra, 2 Important, обе воспроизведены и исправлены. Concurrent read-modify-write заменён транзакциями IndexedDB, ACK сверяет payload; черновик отделён и не теряется на fit/choice/storage-event. Промежуточные Web Locks над localStorage не выдержали браузерную проверку; финальный вариант использует authoritative DB, кэш не определяет ревизии.
- Ruling: при недоступном IndexedDB отзыв живёт в текущем окне, UI прямо это сообщает. Это сохраняет возможность отправить отзыв без ложного обещания сохранности после закрытия.
- Финальная проверка: 195/195, HTTP stub PASS; две вкладки × четыре одновременные пары правок = +8 revisions, конфликтов 0; offline/reload/retry и desktop/mobile PASS. $0 / 0 новых вызовов. Сводка и review — eval/live-feedback; итог docs/LIVE_FEEDBACK_2026-10-31.md.
