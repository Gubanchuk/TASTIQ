# Живая проверка production — 02.11.2026

Запрос владельца: «потестируй на живом сайте всё ли работает», https://tastiq-drab.vercel.app/. GET/api/ai/status подтвердил enabled:true, model gpt-6.1-sol. Проверяется путь желание → вопросы → понимание/исправления → выдача → выбор/знакомство/замена → библиотека/вечера, все4 раздела, перезагрузка/назад и узкий экран. Тестовые ответы синтетические, не human labels.

Перед платным прогоном обнаружен пробел наблюдаемости: production сохранял usage только в временный server journal; браузер не получал receipts, а тестовые отзывы смешивались бы с обычными. Добавлен opt-in QA-сеанс через qa_run в URL, сохраняемый только в sessionStorage. Он изолирует localStorage namespace и IndexedDB, помечает fetch, исключает QA-строки из обычного журнала, сохраняя валидацию и AI access/spend. Normal traffic не получает QA metadata и использует прежние stores/API.

Серверный AsyncLocalStorage привязывает QA receipt к текущему HTTP: точные model/responseId/status/usage/cost/reserve/request hash, без ключей, промптов и outputs. QA может только понизить свой reserve, ceiling$0.25 и максимум1 model call на HTTP; unknown usage останавливает следующую отправку. Это не общий production budget. Режим legacy в QA перенаправляется в изолированную библиотеку до открытия owner stores; обычный legacy не меняется.

Новый оплачиваемый этап: max$0.45 и12 модельных вызовов из действующего разрешения data/api-test-authorization-2026-11-01.json; старые12 immutable media receipts не повторяются. В global PaidBudget добавляются явно помеченные внешние observation descriptors с фактическими response usage; они не являются сохранёнными Responses input и не предназначены для replay.
